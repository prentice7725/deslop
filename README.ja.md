# kouetsu

[English](README.md) | [한국어](README.ko.md) | 日本語

kouetsu は、他人が読む文章のための Claude プラグインです。名前は「校閲」から取りました。文章を出す前に、事実関係と前後の整合性を確かめる編集の仕事です。AI っぽく聞こえる言葉を探して消すのではなく、読み手が何を代わりに払わされるかを、内容、明確さ、表面のパターンの順に Claude に点検させます。

## ここでいうスロップ

スロップとは、書き手が省いた手間を読み手が払わされる文章です。何が正しいのか、何が大事なのか、文が何を言っているのかを、読み手が自分で見きわめなければなりません。人が書いた文章でもスロップになりえますし、モデルが書いた文章だからスロップだとは限りません。

スキルは三つの層を順に点検します。上の層が空のままでは、下の層を直しても意味がないからです。

1. 内容: 伝えることがあり、書き手がその内容に責任を持てるか
2. 明確さ: 文を解読せずに読めるか
3. 表面: 読む前に読み飛ばされる定型パターンがないか。たとえば「単なるXではなく、Yです」や、段落の内容を繰り返すだけの締めの一文

## いつ使われるか

他人が読む文章を書く、書き直す、レビューするよう頼むと、Claude がこのスキルを読み込みます。スキルの名前を出す必要はありません。PR の説明、コミットメッセージ、README、設計書、仕様書、障害の振り返り、報告書、提案書、メール、チームへのお知らせなどです。依頼がこうした作業かどうかは Claude が自分で判断するので、見落とすこともあります。確実にするには「kouetsu で」と名前を付けてください。

コードはレビューせず、小説・詩・一行の回答には使いません。

どの言語の文章にも使えます。韓国語・日本語・英語には、`references/` に言語ごとのパターン一覧があります。それ以外の言語でも、最初の二つの層と、すべての言語に共通するパターンの表（`SKILL.md` にあります）は使えますが、言語ごとの一覧はありません。

## インストール

kouetsu は、スキルを一つ含む Claude プラグインです。Claude Code と Claude アプリで動きます。Markdown と JSON のファイルだけでできていて、コードを実行する部分はありません。

### Claude Code

Claude Code で次の二つのコマンドを実行します。

```
/plugin marketplace add prentice7725/kouetsu
/plugin install kouetsu@prentice7725
```

更新するときは `/plugin marketplace update prentice7725` を実行し、新しいセッションを始めます。

インストールせずにローカルのコピーで試すときは、クローンしたフォルダの親フォルダで `claude --plugin-dir ./kouetsu` を実行します。

### Claude アプリ

Web とデスクトップアプリの Claude のことです。スキルは Free、Pro、Max、Team、Enterprise プランで使え、コード実行がオンでないと動きません。個人プランでは Settings > Capabilities でオンにします。Team と Enterprise ではオーナーが組織の設定でオンにし、メンバーがプラグインを追加できるかどうかも組織の設定で決まります。Plugins メニューが見当たらないときは、オーナーに確認してください。そのうえで、次のどちらかの方法でプラグインを追加します。

- Customize > Plugins > Add > Add marketplace に `https://github.com/prentice7725/kouetsu` を入力します。アプリがこのリポジトリを追うので、更新を受け取れます。
- GitHub の Code > Download ZIP でリポジトリをダウンロードし、Customize > Plugins > Add > Upload plugin からアップロードします。アプリはそのコピーを持つので、リポジトリが更新されたら新しい ZIP をアップロードし直してください。

メニュー名は英語の画面に合わせています。

### スキルだけを使う（Claude Code）

Claude Code でプラグインの仕組みを使わずにスキルだけを使うときは、`skills/kouetsu` フォルダを `~/.claude/skills/kouetsu` にコピーします。更新するときは、もう一度コピーします。

### ファイル

```
kouetsu/
├── .claude-plugin/
│   ├── plugin.json           # プラグインの情報
│   └── marketplace.json      # /plugin marketplace add がプラグインを見つけるためのもの
├── skills/
│   └── kouetsu/
│       ├── SKILL.md          # 三つの層と作業手順
│       └── references/
│           ├── ko.md         # 韓国語のパターン
│           ├── ja.md         # 日本語のパターン
│           └── en.md         # 英語のパターン
├── README.md, README.ko.md, README.ja.md
└── LICENSE
```

`SKILL.md` は、トークンを節約するために英語で書いています。

## データ

kouetsu はコネクタを追加せず、ネットワークへの通信もしません。何がどこで動くかは次のとおりです。

- スキルは Claude への指示です。Claude は、依頼を受けたセッションの中で文章を読みます。
- パターンを数えるとき、Claude はもともと持っている検索ツール（Claude Code の Grep など）を使います。プラグインはスクリプトを追加しません。
- 長い文章の別レビュー（使い方を参照）は、Claude Code では同じセッション内のサブエージェントとして動きます。サブエージェントを起動できない環境では、文章を含むプロンプトを Claude が渡し、新しい会話に貼り付けるかどうかはユーザーが決めます。

## 使い方

### 書く

いつもどおり文章を頼んでください。例：「このブランチの PR の説明を書いて」

書く前に、Claude は受け取った材料をもとに五つの問いに答えます。誰が読むか、読んだ後に何ができるべきか、要点は何か、主張にどんな根拠が要るか、この文章が何を加えるか、です。材料から答えられない点は、Claude が仕分けて扱います。

- 前例や通常の慣行で決められるなら、Claude が決め、理由を書き、ユーザーが覆せるように Claude の判断だと明示します。
- ユーザーの業務ルール・費用・人・方針で決まることなら、ユーザーに任せます。任せ方は文章の長さで変わります。

| | 長い文章 | 短い文章 |
|---|---|---|
| 例 | 設計書、報告書、提案書、記事など、複数の段落があり読み手が時間をかけて読む文章 | メッセージ、メール、コミット、短い回答、一、二段落の要約 |
| ユーザー次第の点 | 下書きの前に Claude が質問します。一度に一つか二つずつ | 質問せずに書き、該当箇所ごとに `[要確認: 何を]` を文章の言語で残して、誰が答えられるかと何が止まるかを書きます。英語の文章なら `[needs confirmation: what]` です |
| 構成案 | 下書きの前に見せます | なし |
| 別レビュー | あり（下記参照） | なし |

長い文章か短い文章かは Claude が決めます。変えたいときは伝えてください。短い文章として扱う、質問や別レビューを省く、短い文章でもレビューする、といった指示ができます。

### 直す

既存の文章を kouetsu で直すよう頼んでください。例：「この報告書を kouetsu で直して」。Claude は事実関係と書き手の文体を保ち、点検に引っかかった文だけを直します。原文にない行為者・数値・出典は補いません。長い文章ならユーザーに質問し、短い文章なら `[要確認: 何を]` で示します。

### 診断する

文章を kouetsu で診断するよう頼んでください。例：「この仕様書を kouetsu で診断して」。Claude は何も書き直しません。文に番号（`[S1]`、`[S2]`、…）を付け、問題ごとにタグを付け、層ごとに報告し、欠陥のある文の割合を示します。

| タグ | 層 | 意味 |
|---|---|---|
| `[blindspot]` | 内容 | 読み手が推測しなければならない、または読み手にない知識を前提にしている |
| `[inconsistent]` | 内容 | 文章の二か所が食い違っている |
| `[actor]` | 明確さ | 誰が何をするのかを文が隠している |
| `[vague]` | 明確さ | 言葉や数値が何を指すのか、読み手に分からない |
| `[empty]` | 明確さ | 消しても失うものがない |
| `[buried]` | 明確さ | 失敗・リスク・依頼が、読み手の見落とす位置にある |
| `[pattern:名前]` | 表面 | 一覧にある定型パターン |

盲点を探すとき、Claude は読み手がこの文章に持ってくる質問を5〜10個作り、文章だけを見て一つずつ答えます。

短くした例です。入力：

> ログイン処理の改善の実施を行いました。これは単なるバグ修正ではなく、パラダイムの転換です。一部のテストで問題がありましたが、全体として良好と考えられます。

診断：

> 内容：要点と根拠がありません。何が変わったのか、マージしてよいのかを言っていません。
> [S1] `[actor]` `[pattern:「〜を行う」]` 誰がログイン処理の何を変えたのか？
> [S2] `[empty]` `[pattern:否定対比]`
> [S3] `[buried]` `[vague]` どのテストが失敗し、それはマージを止めるのか？
> 欠陥のある文：3文中3文。

### 長い文章の別レビュー

書き手は自分の文章の矛盾を見落とします。また、すでに知っているので、文章から抜けていることにも気づけません。そのため長い文章では、二人目の読み手が完成した文章を点検します。二人目の読み手は、文章と、想定読者を説明した一行だけを受け取り、`[inconsistent]` と `[blindspot]` を報告します。それを Claude が直します。

- Claude Code では、Claude が二人目の読み手をサブエージェントとして動かします。
- サブエージェントを起動できない環境では（環境によって異なります）、新しい会話に貼り付けるプロンプトを Claude が渡し、ユーザーが結果を持ち帰ります。

文章をもう一度読んで報告を書く分のコストがかかります。別レビューができなかったときは、Claude が文章を渡すときにそう明記します。

### パターンを数える

モデルは目で数えるとよく間違えます。そのため Claude は、パターン、太字、見出しを検索ツールで一つずつ数えます。Claude Code では Grep、Claude アプリではコード実行環境の `grep -c` などです。多く出たことは見直す理由であって、判定ではありません。

## 常に適用したい場合

スキルは、Claude が文章を書く・レビューする作業だと判断したときだけ読み込まれます。Claude Code の作業報告のように毎回出る文章にも適用するには、Claude が必ず読む場所に要点を書いておきます。Claude Code では `CLAUDE.md`、Claude アプリではプロジェクトの指示です。

```markdown
## Writing
- Put the conclusion, result, or request in the first sentence.
- Name the actor in every sentence. Replace pointers and labels coined during the work with real names.
- Separate what was verified from what was not.
- Delete sentences that carry no information.
```

ルールが英語でも、どの言語の出力にも効きます。書き換えてもかまいません。

## 限界

- この点検は下限です。通過しても良い文章になるとは限りません。
- 表面のパターンだけを消すと、見分けにくいスロップになるだけです。内容と明確さを先に直します。
- 文章に責任を持つのは、それを送り出す人です。スキルはその人が判断すべき点を示すだけで、判断を代わりにはしません。
